- [x] **[cybersecurity]** Cloudflare Project Glasswing: harness architecture for AI-assisted security research at scale

    **What it is:** Cloudflare published a detailed post on using Mythos Preview against 50+ of their own repositories. Key findings: exploit chain construction (Mythos chains low-severity bugs into working proofs autonomously) and proof generation loop (find → write PoC → compile → run → read failure → retry) are Mythos's distinguishing capabilities vs prior models. Organic refusals exist but are probabilistically inconsistent — same task framed differently can produce opposite outcomes, so they cannot serve as a complete safety boundary. Harness stages: Recon → Hunt (50 concurrent narrowly scoped agents) → Validate (adversarial second agent) → Gapfill → Dedupe → Trace (cross-repo reachability) → Feedback → Report. Cloudflare's main takeaway: patch speed is not the answer; architectural resilience (defenses-in-front, isolation between components, simultaneous rollout) is.

    **Why it matters:** This is the most detailed first-party writeup of how Mythos is actually used in production security research. Directly expands what the wiki currently knows about Mythos's capabilities, limitations, and operational patterns. Also adds a concrete harness architecture pattern to `wiki/training/` or `wiki/workflows/`.

- [x] **[coding]** Shopify's Claude Code patterns — LLM proxy, parallel agents, CLAUDE.md as team infrastructure

    **What it is:** Detailed tweet synthesizing Shopify's internal Claude Code practices (from a Bessemer conference writeup). Five concrete patterns: (1) LLM proxy — tool-agnostic centralized gateway routing Claude Code, Copilot, and Cursor through one infrastructure layer for cost control and model swapping; (2) parallel agents in separate terminals for independent tasks; (3) critique loop — agent proposes, critiques, revises, critiques revision before final answer; (4) CLAUDE.md committed to git and shared across all 23,000 engineers with a ~60-line limit ("stuffing it makes performance worse"); (5) permission config: allow read/write/test/lint/commit, deny push/deploy/drop/secrets. Result: 20% productivity gain, 70%/30% strategy-to-execution flip vs 30%/70% in 2024. Q3 target: 90% autonomous coding.

- [ ] **[coding]** HTML over Markdown for agent-produced outputs

    **What it is:** Thariq Shihipar (Anthropic) posted "The Unreasonable Effectiveness of HTML" (4.4M views in 16 hours). Karpathy backed it. Simon Willison changed his mind. Core argument: when agents produce documents for human one-time consumption or agent-to-agent handoff, single-file HTML outperforms Markdown — richer rendering (tables, charts, collapsible sections, JS), no server needed. Decision rule: Markdown when humans will edit the raw format; HTML when agents produce it and humans consume the rendered result. Wrinkle: Slack/Google Docs/GitHub diffs don't yet handle self-contained HTML well.

    **Why it matters:** Affects harness design and output format conventions. Worth capturing as a pattern in `wiki/training/` or extending `wiki/concepts/harness.md`.
