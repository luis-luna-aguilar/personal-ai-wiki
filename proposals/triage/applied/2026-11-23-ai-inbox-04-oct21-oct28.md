- [x] **[agents]** Anthropic Applied AI: fold subagents into one agent loop with skills and tool search

    **What it is:** A Claude guide (about 2026-10-24) reports that across enterprise deployments, one agent with skills often beat both one big prompt and orchestrator-plus-subagents on quality, cost and latency. One customer saw about 2x faster runtime. It names the failure modes of org-chart architectures (Conway's law): subagent sprawl, the "Frankenprompt", localized evals and lossy handoffs.

    Its recipe:
    - The target design is one model and one context running an open tool loop with harness budgets. The planner is also the executor.
    - Procedure goes into skills; hard limits, approvals and per-user permissions go into tools.
    - Group tools by intent, because tool choice degrades past 30–50 definitions; use tool search with deferred loading.
    - A central team owns the system prompt and the end-to-end eval set; 10 golden examples are enough to start.
    - Fold subagents one at a time, merging the most-used, tightly coupled pairs first. Diff which tasks flipped, and run each task more than once.
    - Keep subagents only for context bloat, parallel throwaway contexts, or tool-selection conflicts.

    It ships a migration kit plus `/claude-api build-eval`, `prompt-audit` and `cost-optimize`, and `/skill-doctor`.

    **Why it matters:** `workflows/multi-agent-coordination.md` and `workflows/agent-loop-design.md` say when to split work, but have no vendor guidance on when to fold it back, no 30–50 tool ceiling, and none of these named tools. `concepts/automated-harness-optimization.md` covers only `/claude-api hillclimb`.
