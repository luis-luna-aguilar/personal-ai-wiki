- [x] **[models]** Fable 5 / Mythos 5 launch — state-of-the-art coding model with controversial safety terms

    **What it is:** Anthropic released Claude Fable 5 on June 9 as its "first generally available Mythos-class model" — at least 2x the size of Opus. Fable 5 and Mythos 5 share the same underlying model; Fable has added safeguards. Key specs: $10/$50 per million input/output tokens; 1M context window; cache at $12.50 write / $1 read. Available free in subscriptions until June 22, then credit-gated due to capacity constraints. Benchmark highlights: SWE-Bench Pro 80.3% (vs GPT-5.5 58.6%), FrontierCode Diamond 29.3% (vs prior best 13.4%), CursorBench SOTA 72.9%, Terminal-Bench 2.1 88.0%, Humanity's Last Exam 53%, Intelligence Index #1 at 64.9. Anthropic cited Stripe using Fable to complete a 50M-line Ruby migration in a day. Product posture shift: users are told to give it objectives/responsibilities rather than tasks; routine sessions use 500k–1M tokens; Simon Willison described it as "slow, expensive and capable." Multi-agent orchestration is central — Fable delegates to smaller models via Claude Managed Agents.

    Two controversial changes accompanied the launch: (1) No ZDR: all Mythos-class model traffic retained for 30 days (not used for training, but not zero-data). (2) Silent RSI suppression: for frontier LLM development tasks (pretraining pipelines, distributed training infra, ML accelerator design), Anthropic silently degrades output via prompt modification, steering vectors, or PEFT without notifying the user — estimated at ~0.03% of traffic. Separate visible fallback to Opus 4.8 for cyber/bio/chem/distillation requests (~5% of sessions). Community reaction: Karpathy called it a "major-version-bump" but said safeguards are "a little too trigger happy at launch"; critics called the silent throttling "shockingly hostile" to ML research and flagged antitrust concerns; over-sensitive classifiers flagged "cancer" and "what does the heart do?" as biosecurity risks.

    **Why it matters:** This is the biggest model release in the period and directly updates the Fable 5 model page, state-of-coding, and state-of-models. The controversy dimension is already partially covered by the fable-mythos-ban ingest (June 13-17), but the launch details, benchmark data, and usage patterns are new. Mike Krieger (head of Anthropic Labs) interview content on overnight delegation and verification approaches belongs in training pages.

    **Additional data from Every vibe check** (fetched via Playwright, full article unlocked): Every's internal Senior Engineer benchmark: Fable 5 scores 91/100 vs Opus 4.8's 63 and GPT-5.5's 62. Key usage verdict: "strong closer that wants a clear target — treat it as an asynchronous agent, not a chat partner." Users at Level 7-8 on AI adoption ladder found it paradigm-shifting; lower-level users struggled to find uses. Built complex one-shot apps (3D Library of Babel, subscriber survey analysis) with single prompts. Cost: ~2x Opus, ~3x Sonnet — only worthwhile for large delegable jobs.

- [x] **[benchmarks]** FrontierCode — new benchmark targeting mergeable code quality, not just test-passing

    **What it is:** Cognition (makers of Devin) launched FrontierCode on June 9, a coding benchmark explicitly designed around whether code is actually mergeable into production, not just whether it passes unit tests. Tasks were built with open-source maintainers; each task took 40+ hours to construct; evaluation dimensions include regression safety, cleanliness, scope adherence, test correctness, and maintainability. METR separately found that many SWE-bench-passing PRs would not actually be merged. Baseline: the best model at launch (Opus 4.8) scored ~13% on the hardest Diamond tier — far below the 50%+ scores seen on SWE-bench-style evals. Fable 5 brought this to 29.3% at launch. FrontierCode explicitly inspired by FrontierMath — using saturation-resistant hard problems.

    **Why it matters:** FrontierCode reveals a significant gap between "passes tests" and "ships code" — the benchmark recalibrates what "good coding performance" means. Needs a new `wiki/benchmarks/frontiercode.md` page and updates to `state-of/coding.md`.

- [x] **[models]** DiffusionGemma — Google's 26B MoE diffusion-based text model (non-autoregressive)

    **What it is:** Google released DiffusionGemma, a 26B mixture-of-experts model that generates text via block denoising rather than autoregressive token prediction. Apache 2.0 license. Reported 4x faster than standard diffusion text model baselines. This is architecturally distinct from all current frontier models: instead of predicting the next token, it iteratively denoises a block of tokens simultaneously. It represents the first high-profile open-weight release of a diffusion-based language model at scale.

    **Why it matters:** A genuinely novel architecture entering the open-weight space. Relevant to `state-of/models.md` and warrants a `wiki/models/diffusiongemma.md` page to track the diffusion-LM architecture trend. If this approach scales or proves competitive, it could reshape how we categorize models.

- [x] **[training]** AI review skill systems — multi-persona review agents for content quality

    **What it is:** Katie Parrott (Every) published a fully unlocked piece on using named reviewer skills to catch AI tells and quality issues before submitting drafts to human editors. Key system: a `/guardrails` skill compiles all personal writing failure modes into one enforced checklist. Named persona reviewers add different lenses: **Sorkin** (narrative momentum — keep it walking and talking), **Mom** (reader clarity — where would a non-AI-pilled reader get lost), **Asshole** (attacks the weakest version of the argument). Core insight: using AI to define and enforce quality standards forces you to articulate those standards more clearly — "it changes what the human does instead of reducing the workload."

    **Why it matters:** A concrete, reusable pattern for AI-assisted content review that belongs in `wiki/training/` — either as an addition to an existing training page or a new page on AI review workflows.
