    **What it is:** Anthropic research post (fetched 2026-11-23; forwarded 2026-11-07) defining agent memory as cross-session context the agent writes itself, then reporting evals. On CL-Bench 1.0 (fresh session per question plus a persistent memory directory), Sonnet 4.6 only produced untested theories, Opus 4.7 consolidated notes, and Opus 5 was the first to "close the loop" with validated rules; Opus 5.5 and Sonnet 5.5 match it. Telling strong models a memory folder exists beats giving fixed write rules ("record only failures" cut most of Opus 5's gain), while prompting Sonnet 4.6 to read memory and test theories nearly doubled its score. In Pokémon Red, Sonnet 3.7 wrote 413 files in 225 folders and won one badge; Fable 5 wrote nine files plus a `global.md` dashboard and won four. Dreaming (reviewing memory against transcripts) fixed a wrong note that otherwise kept Claude stuck; a dreamed wiki over Stainless's ~350k internal files (~420M tokens) rose from 13% to 48% of graded criteria across 2→128 sessions, and wiki plus search reached 61% vs 53% for search alone while saving ~20k tokens per question. On a merger Q&A set, wiki 87% vs search 73%; on one Harvey LAB task the wiki gave no gain, and on another it grew larger than the source documents. A self-reflection loop rewrote the wiki-building instructions (one page per contract, verbatim terms) and moved a brief from 72% to 100% of criteria. It also documents Claude Code auto memory loading only the first 200 lines / 25 KB of `MEMORY.md`.

- [x] **[agents]** Framer Harness 2 — executing agent-written JavaScript while it streams, with early cancellation

    **What it is:** Framer replaced its DSL-command harness with one where the model writes a single JavaScript program against the document tree. Incoming code is parsed into complete statements ("cells") and run in a Web Worker as it arrives, so canvas edits appear before generation ends. A failed precondition, early return or terminal error cancels the rest of the stream, saving output tokens, while edits already applied stay. Recoverable write errors are clamped or skipped and reported at the end; dot-notation and sparse-array patches cut output tokens; an in-memory document copy allows synchronous reads. External agents (Claude Code, Cursor, ChatGPT Desktop) now submit one program over MCP to the same harness. Reported: 43% fewer tool steps (stated as "2x fewer" earlier in the post) and 39% fewer cached input tokens per message, no measured quality loss. Framer credits the prior paper "Executing as You Generate" (arXiv 2604.00491) for the same idea in Python.

    **Why it matters:** The wiki has "code mode" only as a Pi 1.0 feature line; it has no page or section on stream-time execution and cancellation as a harness pattern. Fits `concepts/harness.md` (or the agent-loop workflow page) as one production example plus the paper.
