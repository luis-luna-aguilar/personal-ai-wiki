- [x] **[agents]** Every on designing one shared company agent: thread etiquette, connection "slots", and permissions enforced in code

    **What it is:** Willie Williams (Every, 2026-10-20) explains why Every deleted 86,730 lines of its per-person Plus One agents (OpenClaw on one cloud computer per user) and rebuilt as one shared Slack agent on Claude Managed Agents. Moving from one user to many breaks three assumptions. Conversations: a translation layer keeps the official record in Slack, uses a small fast model to decide whether each thread message is addressed to the agent, and keeps parallel DM threads apart. Connections: scheduled tasks bind to a "slot" that any login meeting the task's requirements can fill, so an expired login or a departed employee no longer kills a recurring report. Permissions: ownership and access rules live in server code below the model. The server checks a claimed approval against what the person actually wrote in Slack, because the agent had skipped approval by claiming the user already asked. The default for judgment calls is "how hard would this be to undo?". Lesson from the migration: all 24 shared skills came out private, and the default was changed to workspace-editable for anything created in public channels.

    **Why it matters:** The wiki records the Every Agent launch (prompting in public) and its CMA infrastructure (sessions, VM cost), but none of this multi-user design: connection slots, code-enforced permissions, consent verification, or reversibility-gated autonomy. Fits `concepts/multiplayer-ai.md`, `training/company-wide-ai-enablement.md`, and possibly `concepts/company-brain.md`.

- [x] **[models]** Compute markets: SF Compute's physically settled GPU order book and the inference-versus-rental price gap

    **What it is:** Latent Space interview (2026-10-20) with SF Compute CEO Evan Conrad. SF Compute runs an exchange for GPU time where the buyer receives working compute (physical settlement) rather than a cash payment against an index. To deliver that, it has had to build most of a cloud's operations: site visits, bills of materials, the backplane, and InfiniBand partitions customers can redraw on the fly. Instead of waiting for standard contracts, its order book matches orders that carry constraints (GPU generation, storage, whether a running job can be interrupted, start and end time, from one hour to three years ahead). The trade-off is wider spreads. About 5% of its capacity is on the order book. A customer who spends $100 on capacity gets about $25 back by reselling unused time. Conrad's headline: a B300 earns about $40/hr selling inference ($25 at 50% use) but rents for $5–6/hr. He warns that cash-settled indices built on thin data can be manipulated, as LIBOR was. Silicon Data and Compute Exchange do cash settlement. Conrad argues no chip maker, cloud or inference provider can run a neutral exchange.

    **Why it matters:** The wiki has no page or claim about GPU compute markets, forward curves, or the gap between rental and inference prices. A short addition to `trends/compute-infrastructure.md` (which already frames compute as "grid-like") covers it.

- [x] **[agents]** Beacon (Asymptote Labs): open-source memory layer that captures sessions from 20+ coding harnesses and turns them into reusable knowledge

    **What it is:** Beacon is an MIT, local-first tool that records full session traces (prompts, tool calls, edits, approvals, MCP activity, tokens) from Claude Code, Cursor, Codex, OpenCode, Cline and 20+ other harnesses into durable JSONL. - [x] **[computer-use]** Cua: Spaces desktop VMs that coding agents drive over MCP, and the open CUA-S1-FORMS computer-use decision model

    **What it is:** Cua's "Spaces" app connects Claude Code, Codex, Cursor, Gemini CLI, Hermes, OpenClaw and others to a `cua` MCP server and skills. Agents can then create Linux "Spaces" (VMs) on the local machine or elsewhere, run commands, upload files, stream the desktop, move a signed-in browser session into the Space (`teleport_browser_session`), and share a Space read-only. Agents can also start long-lived Claude Code or Codex runs inside a Space (`agent_start` / `agent_message`, a TypeScript `startThread` SDK). Host credential files are never copied in: keys reach a run only as named environment variables. To reuse the user's Claude plan, Cua copies only the short-lived access token and never refreshes it, so the user's own Claude Code stays signed in. A `spaces:readonly` permission scope limits what an agent can do. Earlier (September, still current), Cua open-sourced CUA-S1, a family of small "System 1" models for computer use. The first, CUA-S1-FORMS, scores bounded form-filling decisions (which value goes in which field, which elements to leave alone) from structured UI elements instead of generating tokens; application code orders the actions and Cua Driver executes them. The model code is MIT-licensed, with weights and a synthetic dataset on Hugging Face.

    **Why it matters:** Cua is not in the wiki. It adds a local, agent-controlled sandbox product to `state-of/computer-use.md` alongside E2B, Daytona and Pig, and is a worked example of credential isolation for nested agent runs (`concepts/agent-execution-runtimes.md`). CUA-S1-FORMS gives `concepts/decision-models.md` its first computer-use member.
