# Proposal: gdp-ts (Ghosts of Departed Proofs for TypeScript)

## Summary

### In short
A whole class of authorization bugs can be made type errors, so neither a person nor a coding agent can skip the check and still get the code to compile. gdp-ts does this in TypeScript: sensitive functions demand a proof about their exact arguments, and only a trusted module can create that proof. The README claims almost no runtime cost and about 0.3 ms of type-check time per call site. The proposal adds one oracle bullet to the coding-evals training page and one prerequisite to the software-factory workflow. The reason to hesitate is that the evals page is already at its length ceiling.
[[#Open questions|Open questions: 2 to answer.]]

### The source
gdp-ts is a small open-source (MIT) TypeScript package from the GitHub repository rauchg/gdp-ts. It brings a Haskell and Rust idea, "Ghosts of Departed Proofs", to a common web-backend bug. In a typical route, one line checks that the user is a project admin and the next line changes a project setting, but nothing in the code ties the two together. If a developer drops the `await`, or the rule changes and one call site keeps the old check, the write still compiles and runs.

The package fixes this in three steps. First, `name()` gives a runtime value, such as a project id, a compile-time label, so the compiler can tell two ids apart even though both are strings. Second, a small trusted module runs the real check and returns a proof object that is tied to those exact named values. Third, the sensitive data-layer function requires that proof as an argument. Calling it with a raw id, a proof about a different project, the wrong proof, or no proof is a compile error. At runtime a proof is a tiny frozen object, hence "ghosts". A cast such as `{} as Proof` would get around the types, so ESLint and Oxlint presets block forged proofs and proofs created outside the trusted folder. The package also includes an agent skill, installed with `npx skills add rauchg/gdp-ts`, that guides coding agents and people toward the pattern and advises how much of a codebase is worth proving. It complements policy engines and schema validators rather than replacing them.

```
# rauchg/gdp-ts — Ghosts of Departed Proofs for TypeScript (GitHub)

README for gdp-ts, an MIT-licensed TypeScript library, linter preset, and agent skill that implements "Ghosts of Departed Proofs". Sensitive functions demand a compile-time proof about their exact arguments, minted only by a trusted module, so authorization ("can this user read this resource") and entitlement ("does this user pay for this resource") bugs become type errors that humans and coding agents cannot easily introduce. The README gives no release date; the fetch date (2026-10-19) stands in.

## Key claims extracted

- Three steps: `name()` gives a runtime value a compile-time-only name; a trusted module checks a fact and returns a `Proof` (or null); sensitive functions demand the proof about their exact named arguments
- Calling a sensitive function with a raw id, a proof about a different value, the wrong proof, or no proof is a compile error
- Middleware only authenticates; the check happens in the route body, and a data layer that demands proofs is safe to export to routes, Server Actions, and jobs
- ~Zero runtime overhead: a proof is a frozen `{ kind }` object; no extra queries or dependencies
- Type-check cost about 0.3 ms per authorized call site on a cold TypeScript 7 check; grows with usage, not codebase size
- ESLint and Oxlint presets block forging proofs with `as` or minting them outside `proofs/`
- Agent skill (`npx skills add rauchg/gdp-ts`) is plain Markdown, guides agents and humans through the pattern, and includes "where to stop" advice (an ease-to-rigor slider)
- Incrementally adoptable; requires TypeScript 5.4+
- Complements, not replaces, policy engines (CASL, Oso, Cerbos, OpenFGA), branded types, and validation libraries (zod, valibot); a policy engine can run inside a proof function
- Pragmatic TypeScript port of Haskell `gdp` and Rust `departed` / `mononym` / `gdp_rs`
```
