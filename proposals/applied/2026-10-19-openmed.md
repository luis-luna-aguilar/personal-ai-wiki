# Proposal: OpenMed (local-first clinical NER and PII de-identification SDK)

## Summary

### In short

Hospitals no longer need a cloud API to strip patient identifiers and pull clinical facts out of notes: OpenMed packages both as one open-source SDK that runs on laptops, phones and in the browser. It ships a curated catalog of 2,200+ medical models, de-identification in 42 language codes, and three model families built on OpenAI's Privacy Filter design behind one API. The proposal adds an OpenMed tool page, a leader line on State of Healthcare, and a cross-link on OpenAI Privacy Filter. Reason to hesitate: the subcategory is a stretch, and the date is the capture date.

[[#Open questions|Open questions: 1 to answer.]]

### The source

OpenMed is a GitHub project by Maziyar Panahi that describes itself as local-first healthcare AI. It does two jobs on hardware the user controls. The first is clinical named-entity recognition (NER): pointing a model at a note and getting back the diseases, drugs, anatomy or genes it mentions, each with a confidence score. The second is de-identification: finding names, dates, ID numbers, phone numbers and addresses and then masking, replacing, hashing or date-shifting them. The README says the configuration can target the 18 identifier categories of HIPAA's Safe Harbor rule, but states plainly that using the SDK does not by itself make a deployment HIPAA-compliant.

The same models run in Python on CPU or GPU, on Apple silicon through MLX and a Swift package, on Android through Kotlin, in the browser, and as a Docker-ready REST service. Privacy is handled by three model families on the architecture OpenAI released as Privacy Filter: the original weights, a version trained on NVIDIA's Nemotron-PII data, and an MLX build, all called through the same `extract_pii()` and `deidentify()` functions. Of the 42 supported language codes, 35 are backed by a model. Agent Skills and an MCP server let coding agents such as Claude Code and Codex build these pipelines. The SDK is Apache-2.0; model and dataset licenses vary. A "clinical brief" demo uses synthetic stand-ins, not trained models.

# OpenMed

Open-source, local-first SDK for clinical text: named-entity recognition (diseases, drugs, anatomy, genes) and PII/PHI de-identification that run on hardware the user controls, so notes do not have to leave the building to be processed. Maintained by Maziyar Panahi; SDK under Apache-2.0, with model and dataset licenses varying per artifact.

## Current status (as of 2026-10-19)

- Curated catalog of 2,200+ medical models on Hugging Face, mostly specialized NER variants (e.g. disease, pharma, PII, anatomy, gene detection at 109M–434M parameters)
- De-identification by mask, replace (Faker-backed fake values), hash, or date shift; 42 supported PII language codes, 35 of them model-backed
- PII models include three families on the [OpenAI Privacy Filter](../models/openai-privacy-filter.md) architecture (original weights, Nemotron-PII-trained, MLX) behind the same `extract_pii()` / `deidentify()` API
- Runtimes: Python (CPU/CUDA), Apple MLX and a Swift package for iOS, Kotlin/ONNX Runtime Mobile for Android, browser via Transformers.js/WebGPU, and a Docker-ready REST service with auth, no-PHI logging, and batching
- Agent-facing surfaces: Agent Skills for Claude Code, Codex, and OpenCode, an MCP server, and an llms.txt docs index
- v3.0.0 release; 5,400+ GitHub stars as of 9 October 2026

## Why it matters

Most healthcare entries in the wiki are hosted products. OpenMed is the open, on-device counterpart for the step that usually blocks cloud AI in clinical settings: removing identifiers before any text reaches an external model. Its agent skills explicitly tell users to run the pipeline locally on real notes and not to paste PHI into a cloud-hosted agent.

## Weaknesses / caveats

- The README states that SDK use alone does not establish HIPAA compliance; Safe Harbor-aligned categories are implementation aids, and deployment owners must validate privacy behavior and clinical fitness
- Model and dataset terms vary across the catalog and must be checked per model
- The "clinical brief" demo runs on synthetic test doubles, not trained models, and is not clinical validation
- Network paths (model downloads, remote adapters, telemetry-enabled paths) sit outside the local-only boundary

## Key claims extracted

- 2,200+ medical models in a curated catalog; example NER models at 109M–434M parameters (disease, pharma, PII, anatomy, gene)
- De-identification methods: mask, replace (Faker), hash, shift_dates; smart entity merging; HIPAA/GDPR/research policy profiles, signed audit reports
- Safe Harbor-aligned configuration can target the 18 identifier categories; SDK use alone does not establish HIPAA compliance
- 42 supported PII language codes, 35 model-backed; Russian routes to a multilingual placeholder
- Privacy Filter family: `openai/privacy-filter`, `OpenMed/privacy-filter-nemotron` (NVIDIA Nemotron-PII data), `OpenMed/privacy-filter-mlx`; same API, only `model_name` changes
- MLX on Apple silicon: 24–33x faster than CPU PyTorch for the Privacy Filter (median latency per step); batch PII up to 3.3x throughput on CPU, 2.2x on MLX
- Runtimes: Python CPU/CUDA, MLX, Swift OpenMedKit (iOS), Kotlin + ONNX Runtime Mobile (Android), Transformers.js/WebGPU, FastAPI REST service with API-key/JWT auth, no-PHI logging, gRPC, async jobs, dynamic batching
- Agent Skills for Claude Code, Codex, OpenCode; MCP server; llms.txt index
- Clinical brief demo uses synthetic NER/NLI test doubles, not trained-model or clinical validation
- v3.0.0 release; 5,400+ stars (9 Oct 2026 snapshot); companion paper arXiv 2508.01630 (OpenMed NER, 2025)
