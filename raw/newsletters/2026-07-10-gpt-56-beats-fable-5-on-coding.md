**OpenAI unveils its most efficient coding models yet:** The ChatGPT maker just dropped [GPT-5.6](https://openai.com/index/gpt-5-6/) in three tiers named Sol, Terra, and Luna. OpenAI claims flagship Sol leads the Artificial Analysis Coding Agent Index with a score of 80 while using less than half the output tokens of Claude Fable 5. All three models are live in [the API](https://developers.openai.com/api/docs/guides/latest-model) with Programmatic Tool Calling and a parallel-subagent ultra mode. The models also power ChatGPT Work, a new agent with Codex built in that runs across your apps for hours, delivering finished sheets, slides, docs, and web apps.

**Meta debuts its first paid AI model for agentic tasks:** Zuckerberg's AI lab just shipped [**Muse Spark 1.1**](https://ai.meta.com/blog/introducing-muse-spark-meta-model-api/) along with the Meta Model API. This marks a shift from their usual open-weight Llama releases, moving to a hosted model with per-token pricing. The update is built for long agentic tasks. It handles planning across parallel subagents and manages a massive 1M-token context to help big projects finish faster. You can check out the [API right here.](https://dev.meta.ai/docs/getting-started/overview#first-call)

**Ex-GitHub CEO's startup gives AI agents faster Git:** The new venture, named [**Entire**](https://entire.io/blog/an-entirely-new-git-hosting-network), just released its distributed Git network platform. Your code stays on GitHub, but agents can now clone and pull from a nearby mirrored copy. Founder Thomas Dohmke says this setup eliminates the rate limits and latency issues caused by billions of clones hitting a single server. It works with Claude Code, Cursor, Codex, and Copilot. [See how it works.](https://x.com/ashtom/status/2074863476959248876)

## **Your AI coding bill has less to do with the model than you think. Here's why:**


--------------------
View image: (https://media.beehiiv.com/cdn-cgi/image/fit=scale-down,format=auto,onerror=redirect,quality=80/uploads/asset/file/a1a2574a-62d2-4797-a349-74164fc46ce3/pareto.jpg?t=1783685444)
Follow image link: (https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase#:~:text=Figure%201%3A%20Cost%20vs.%20Performance%20on%20our%20benchmark)
Caption: Cost vs. Performance on Databricks’ Benchmark


--------------------
**A benchmark from real PRs.** Databricks created a [private benchmark](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase) by using real tasks their engineers completed in their own codebase. They tested various AI agents on these tasks and graded them using the original pull request tests. The most surprising takeaway: open-source GLM 5.2 performed just as well as Opus 4.8 but cost about 30% less per task.  

**But the bigger gap.** Every model runs inside a harness like Claude Code or Pi. Databricks found that using different harnesses with the same model can double the cost with no meaningful change in quality (see the above image). The efficient harness sent less context each turn and required fewer runs to complete the job.

**Sticker prices mislead too.** In this benchmark, Sonnet 5 actually costs $2.09 per task, while Opus costs only $1.94. Even though Sonnet 5 has lower per-token rates, it ends up being more expensive per completed task. This is because Sonnet 5 takes longer and re-reads more context to get the job done. Ultimately, the only metric that matters is “how much it costs to get a code change that passes your tests.”

**Your repo is already a benchmark. **Databricks points out that teams merging PRs are sitting on a goldmine of evaluation data. Merged PRs capture real intent, and the ones with solid tests come with graders built in. No model has trained on them. The post outlines a [step-by-step method:](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase) pick the right PRs, rewrite their intent into prompts, and hold out the tests for scoring.

## **How to run Codex locally**

Codex usage limits can run out fast, but running it on a local model bypasses the quota entirely. Thibault Sottiaux, OpenAI's head of Codex, [mentioned](https://x.com/thsottiaux/status/2067181377028538431) this in a post back in June.

1. Install Ollama from [ollama.com](https://ollama.com). Codex CLI should already be installed.

2. Pull a model: “ollama pull gpt-oss:20b”

3. Start Codex with the “--oss” flag, which points it at Ollama automatically:

```
codex --oss
```
You can now run Codex locally on your machine, meaning no API bills, no rate limits, and total privacy for your code. [Full setup](https://learn.chatgpt.com/docs/config-file/config-advanced#oss-mode-local-providers:~:text=Amazon%20Bedrock.-,OSS%20mode%20(local%20providers),-Codex%20can%20run) details in OpenAI's docs.
