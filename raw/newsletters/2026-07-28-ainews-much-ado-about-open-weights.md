Everyone say hi to Richard MacManus, our new Head of Editorial [ https://substack.com/redirect/71a5680e-616d-49cf-bfda-43bdf07a2dc6?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]!
The current debate about Open Weights is the kind that creates a lot of grandstanding on a topic, while they wait for a very small set of players that will actually decide how things go (in either direction); this is not very conducive for those of us trying to focus on high signal to noise.
First, there was the open models letter signed by NVIDIA [ https://substack.com/redirect/0ee01557-34be-4f48-88a9-d8f55d4dccb8?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and Microsoft [ https://substack.com/redirect/0281b5cb-240d-4b51-839b-eed459a73162?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], which quickly devolved to memes [ https://substack.com/redirect/4f9a26fa-c55d-4455-9e0c-db0e2020170d?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and memes [ https://substack.com/redirect/a3b8bd92-947a-4685-b4b3-c942557e9650?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and everyone in the ecosystem (who obviously benefit from more open models) piling on to cosign the letter to adopt an already populist stance. Meanwhile, OpenAI was rumored [ https://substack.com/redirect/e481d5f3-e33e-40f6-a294-6d0631807246?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] not to sign it, and then signed it [ https://substack.com/redirect/5ea7e8a5-c51e-46ad-997f-0107f86b9bc6?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and Anthropic did not sign it [ https://substack.com/redirect/d612d117-42bc-41a4-9b04-e5b03dbb964d?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. 
All very predictable, and all somewhat exhausting.
Meanwhile the only people to actually ship open weights this week are likely to be Moonshot AI, which this weekend followed through on their promise to ship Kimi K3, which has now been independently validated [ https://substack.com/redirect/856dcb92-1027-4e33-ac5a-e40aa9d0cabf?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] multiple times to beat Opus 4.8 [ https://substack.com/redirect/efb77557-7fcd-4f72-b48e-89f57226dbfa?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] as hoped, and therefore claim the title of best open weights model in the world.
If you don’t make law, make chips, or make models, we recommend reading the Kimi K3 tech report [ https://substack.com/redirect/bb94b443-89f0-470c-8d0d-00a00f91c6dc?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] rather than 50 tweets of low-perplexity invective by the commentariat to the proletariat.

Moonshot’s Kimi K3 Open-Weights Release and the New 3T-Class Open Frontier
Kimi K3 is the day’s dominant release: Moonshot released Kimi K3 weights, report, and supporting infra as an open-weights package: a 2.8T-parameter MoE, 104B active parameters, 896 experts / 16 active per token, 1M-token context, and native visual understanding per @Kimi_Moonshot [ https://substack.com/redirect/001bca29-bcf7-425a-9cb5-2c97bc6673a8?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. The companion posts also open-source FlashKDA (their Kimi Delta Attention kernels), MoonEP (MoE communication library), and AgentENV (distributed agent environment infra) via FlashKDA [ https://substack.com/redirect/40e062de-6e89-41db-9c7f-6393f5045872?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], MoonEP [ https://substack.com/redirect/3115bca1-fa21-4781-885f-6f2635c57d52?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and AgentENV [ https://substack.com/redirect/ee527e41-911a-4df0-994c-e804d3a6ca62?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. This is more than a model drop; it is a fairly complete recipe for large-scale agentic post-training and serving.
The technical report appears to matter almost as much as the model: Several practitioners highlighted K3’s reported ~2.5× scaling-efficiency improvement over K2, with architecture and training choices centered on numerical stability at extreme scale—see reactions from @eliebakouch [ https://substack.com/redirect/9f25ddc1-8e6b-4549-9754-d7ecbadcc610?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @suchenzang [ https://substack.com/redirect/1f29d880-8c1c-48a0-842c-b707779a64b5?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and @teortaxesTex [ https://substack.com/redirect/528bfd1d-c81c-40e5-a222-f9bac7ba2f93?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. Specific details surfaced in commentary include MXFP4 weights / MXFP8 activations @teortaxesTex [ https://substack.com/redirect/a813f1e4-bdba-4b3a-823c-a0fe7c69e4b6?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], joint training of the vision encoder from scratch for stability @iScienceLuvr [ https://substack.com/redirect/4bc3b7b9-2809-48bf-b657-65db317157b1?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and heavy attention to MoE routing / signal propagation issues. The report reportedly omits total training tokens, which multiple readers noted as a meaningful missing detail @teortaxesTex [ https://substack.com/redirect/6422f63a-3f47-432c-8473-374a21eb096b?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
Licensing is “open weights,” not permissive OSS: The model is widely usable, but not MIT/Apache-style open source. Multiple posts noted a commercial-use restriction: large hosting providers over $20M/year need a separate agreement, and products above 100M MAU or $20M/month revenue must display “Kimi K3” in the UI, per @natolambert [ https://substack.com/redirect/63e9816c-c135-4ec5-913a-15313452ab0b?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @petergostev [ https://substack.com/redirect/1f372c52-beca-4b11-a895-539f125ffaca?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and @ArtificialAnlys [ https://substack.com/redirect/1b281be1-a774-4936-9991-9b2046ee3c34?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. This is a useful signal for where frontier “open” may be settling: source-available / open-weight with business carve-outs rather than OSI-style licensing.

That breadth underscores that open-weight frontier launches are now supply-chain events, not just research announcements.
Open AI Security, Open Weights Politics, and Anthropic’s Position
NVIDIA formally launched the Open Secure AI Alliance: Jensen Huang framed the core thesis starkly: attackers already have strong AI, so defenders need an ecosystem spanning open and closed frontier models, plus shared tooling and research. The flagship statement came from @JensenHuang [ https://substack.com/redirect/000d0d2e-29a3-4b13-9cb1-f1bbf1d8d281?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], with NVIDIA’s formal announcement at @nvidia [ https://substack.com/redirect/634c4c84-fd22-42f7-890f-a466c56ecc65?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. The most technically interesting detail in the messaging was the claim that during the OpenAI/Hugging Face incident, a frontier open-weight model helped contain the intrusion, while a closed model blocked essential forensics—echoed by @AndrewYNg [ https://substack.com/redirect/57278a16-3c0e-40da-876d-8afedf4457bb?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and @ZixuanLi_ [ https://substack.com/redirect/282f2c6c-0065-485d-a6e5-5b1c73ce51d8?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
The alliance quickly accumulated credible infra and tooling members: Confirmed participants posting publicly included Hugging Face @huggingface [ https://substack.com/redirect/3a9503d7-ac15-4410-a4aa-000695fe4ea5?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], LangChain @LangChain [ https://substack.com/redirect/e6729717-dbcf-4dc7-b1ce-fe98c4af6f73?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], Nous Research @NousResearch [ https://substack.com/redirect/c32dbff0-1887-49b6-9404-40665d7b942e?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and support from voices across the open ecosystem such as @UnslothAI [ https://substack.com/redirect/9fe966e4-f9cb-4ae9-a336-09e61ed2a64f?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and @Yuchenj_UW [ https://substack.com/redirect/82347cb5-9439-4d2e-9722-468a3fa48c45?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. The argument is not “open is automatically safer,” but that defensive capability and auditability require open access to models, harnesses, and traces.
Anthropic finally clarified its open-weights stance: After sustained criticism for not signing NVIDIA’s open-weights letter, Anthropic published a position statement saying it has “never advocated for a ban on open-weights models” and instead supports: chip controls on China, anti-industrial-scale distillation measures, and mandatory safety testing for sufficiently capable models, open or closed, per @AnthropicAI [ https://substack.com/redirect/2f0be0b1-ed86-4050-93ea-9756febbb001?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. Reactions split between “reasonable clarification” @signulll [ https://substack.com/redirect/fd3c20c0-2a9a-45b6-91b7-cd423e09b352?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], “good, but still trying to slow frontier diffusion” @jachiam0 [ https://substack.com/redirect/99a0d08f-9521-4c42-9967-e0a2e34aa180?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and more hostile readings from open-weight advocates like @Teknium [ https://substack.com/redirect/4a73393b-4246-43a3-8278-249f4af0c37f?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
Policy pressure is intensifying around pre-release review: Separate reporting suggested the US government may seek up to 30 days of pre-release access to frontier systems for evaluation by agencies such as NSA and CAISI, with open-vs-closed treatment still unresolved, via @kimmonismus [ https://substack.com/redirect/99160342-933c-4c65-8521-81fbededc523?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and @leomschwartz [ https://substack.com/redirect/a1f70125-d2ab-4ce3-98c4-08ec29f65a7d?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. Together with Anthropic’s statement and OpenAI’s Washington briefings, the direction is clear: frontier model release is becoming a governance interface, not just a product launch.
Benchmarks, Evals, and Agent Reliability
K3’s early evals are strong, especially for agents/coding: On Agent Arena, Kimi K3 Max reportedly ranks #1 among open-weight models with +9.75% net improvement, leading across multiple signals including confirmed success and steerability @arena [ https://substack.com/redirect/2bb3a99b-0dc3-47ee-b01a-1e19ef58e5e4?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. It also took #1 overall in Frontend Code Arena among all models in a later post @arena [ https://substack.com/redirect/014edcf9-9315-4cc1-9ded-369aafeaf249?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. Cognition said K3 is the first open-source model they tested that “approaches frontier-level performance” on FrontierCode 1.1, scoring 58.2% with 63.6% pass rate @cognition [ https://substack.com/redirect/d186771e-93e5-497c-ada8-59ada0e658b6?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
Claude Opus 5 also posted strong leaderboard numbers, but practitioner feedback was mixed: Arena reported Opus 5 Max at #1 in Frontend Code Arena and Text Arena with factuality on @arena [ https://substack.com/redirect/08c35f0d-616b-4c50-9bea-377c7323d7fe?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], while WeirdML numbers from @htihle [ https://substack.com/redirect/c0195d81-e52a-4cb3-a76b-9775b61d794a?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] put Opus 5 high/max at 91.6% / 91.8%, roughly tied with Fable 5 max. But several devs reported frustrating real-world behavior—overcomplication, breakage, poor stopping behavior—from @abacaj [ https://substack.com/redirect/af227662-db90-459b-bf6f-b65a4eda3403?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @davis7 [ https://substack.com/redirect/baa03466-1fc6-40ba-9fd3-98592594bda3?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @Teknium [ https://substack.com/redirect/dee3ce8d-710d-4d17-878b-ed0f560c1edb?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and @theo [ https://substack.com/redirect/a9b2a08c-295b-46dc-898c-4b2ee19c7b00?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. As usual, public eval gains and harness-specific production utility are diverging.
New eval work focused on sequential degradation and hidden regressions: @_philschmid [ https://substack.com/redirect/c4e7d396-6828-4bf7-b65a-59b6a8ec5604?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] highlighted EvoCode, an eval built around 26 tasks / 227 sequential rounds in a persistent container, measuring whether agents can follow evolving requirements without breaking earlier behavior. In parallel, @omarsar0 [ https://substack.com/redirect/ea626b63-b55d-42dc-8342-ba43b7225782?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] summarized a paper showing the “regression tax” from agent skills: across nearly 6,000 paired runs, skills generated gains but also broke many tasks previously solved without them. That is a practical warning against naïvely stuffing more procedural skills into context.
Multi-module RL systems are showing “role drift”: Another useful paper summary from @omarsar0 [ https://substack.com/redirect/ecbf7f54-db2d-4fbe-95c9-5d403ed9b347?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] described how end-to-end RL can improve pipeline accuracy while causing modules to quietly abandon intended responsibilities—e.g. a decomposer embedding the answer rather than structuring the problem. This feels increasingly relevant as teams move from single-agent loops to specialized tool/prompt/module stacks.
Model and Systems Infra: From Agentic RL to Streaming VLMs
Microsoft and NVIDIA both shipped notable infra/model updates: Microsoft released Mage-VL 4B, described as a codec-native streaming VLM for live-event understanding, via @HuggingApps [ https://substack.com/redirect/77ba0431-ff34-40be-8ab0-3425669dbef4?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
