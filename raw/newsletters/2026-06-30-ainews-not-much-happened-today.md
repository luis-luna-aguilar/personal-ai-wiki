Brain-computer interfaces and AI-for-science tooling
Brain2Qwerty v2 is the clearest research release of the day. Meta says the system decodes words and semantics, not just characters, from non-invasive recordings in real time, narrowing the gap with invasive BCIs. Community summaries highlighted reported jumps from prior non-invasive results to ~61% word accuracy overall and 78% for the best participant, trained on data from 9 volunteers in controlled typing settings. The key engineering point is not consumer readiness, but that the stack combines raw neural-signal modeling with language modeling strongly enough to make sentence-level decoding practical in the lab. See Meta’s announcement [ https://substack.com/redirect/48852396-ea05-4f7e-be40-47dc7e3b7c61?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], the code/data release details [ https://substack.com/redirect/cf8d964c-efd4-4a0f-91a8-0d990c8e38e8?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @JeanRemiKing’s thread [ https://substack.com/redirect/8b8de8d1-7f7d-4382-9bde-47d5218c2439?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and a cautious external summary from @kimmonismus [ https://substack.com/redirect/d594fc2b-f30b-4513-a71c-e121124c98ad?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ].
The release also became a datapoint for agent-assisted research. @stalkermustang [ https://substack.com/redirect/13723e93-e975-4cc8-a333-00f5fb7e6cb3?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] pointed to Meta’s note that an Auto Research workflow, powered by a coding agent, discovered and implemented improvements that reduced word error rate beyond standard HPO. Whether or not one buys the “vibe-science” framing, the more sober takeaway is that coding agents are increasingly useful for closed-loop experimental iteration on ML systems, not just repo scaffolding.
Inference systems: DSpark, vLLM, and decoding mechanics
DeepSeek’s DSpark was the most substantive inference topic. A long explainer from @ZhihuFrontier [ https://substack.com/redirect/7cd9e894-a382-481e-a699-2135bae71169?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] framed DSpark as an important step in speculative decoding, with emphasis on two ideas: better draft generation and smarter verification scheduling. Reported gains include 30.9% higher accepted length vs Eagle3 and 16.3% vs DFlash on Qwen3-4B, plus production deployment in preview engines for DeepSeek-V4-Flash and V4-Pro. Follow-on commentary from @teortaxesTex [ https://substack.com/redirect/6de7cdd3-b15f-4576-92f6-54516ae92a54?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and @vllm_project [ https://substack.com/redirect/5e35e495-e07e-46d0-8350-f3fcb7cabd47?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] underscored the practical consequence: DSpark looks like a new SoTA single-GPU spec decode path, and the vLLM community is already integrating it.
More broadly, several tweets sharpened the mental model of current inference bottlenecks. @_avichawla [ https://substack.com/redirect/756c1325-659d-410b-a491-86896ef82652?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] gave a solid explainer of prefill vs decode, TTFT vs inter-token latency, and why decode is often memory-bound because of KV-cache reads. This is useful context for why speculative decoding, KV-cache optimization, grouped-query attention, and attention redesigns matter more than raw FLOPs in many production workloads.
NVIDIA/vLLM also pushed practical self-hosting: @vllm_project [ https://substack.com/redirect/ba5d045e-fe1f-45a5-a661-7670ded75d04?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] highlighted a guide for serving Nemotron-3-Ultra 550B with four DGX Spark boxes behind a single OpenAI-compatible endpoint. The notable part is less the stunt than the normalization of private, multi-node frontier-ish inference using standard serving stacks.
Agent harnesses, routing, and multi-model orchestration
The center of gravity in agent systems continues to move from “pick the best model” to harness engineering. @cognition [ https://substack.com/redirect/15895aa2-9316-4360-9ef8-51e314a48b9b?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] launched Devin Fusion, a hybrid-model coding harness claiming 35% cost reduction while maintaining “Fable-level” quality. @walden_yan [ https://substack.com/redirect/725cff97-a5ab-4929-92a0-515bd031ae08?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] described related work around sidekick and mid-session routing, and @jerryjliu0 [ https://substack.com/redirect/513d7155-0b5b-406f-a06d-0da8b84c5ad6?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] noted the cache-efficiency advantage of sidekick-style delegation. The emerging pattern: keep an expensive planner in the loop, hand bounded subtasks to cheaper models, and preserve cache locality/context continuity.
Dynamic subagents became another common motif. @LangChain [ https://substack.com/redirect/ccca9fb6-2b41-4954-8ca6-4d464faccc7a?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], @sydneyrunkle [ https://substack.com/redirect/0c8719bb-0f6b-4aed-b8d3-418395212e51?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and @hwchase17 [ https://substack.com/redirect/a6c29323-4cbf-49cb-b2e6-502a13dfba3c?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] all highlighted workflows where the main agent writes orchestration code rather than merely invoking tool calls. This is notable because it shifts the abstraction from “tool-using chatbot” to something closer to a programmable control plane for large task fanout.
Open routing and retrieval stacks also got more concrete. @LlamaIndex [ https://substack.com/redirect/633441ce-8279-4420-9e97-ceb19d0e1969?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and @jerryjliu0 [ https://substack.com/redirect/ca690aa7-8202-4312-a199-550cc60dacab?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] introduced a Retrieval Harness combining semantic search, grep, file listing, and file reading in one agent loop—essentially a rebuttal to simplistic “grep is all you need” positions also criticized by @max_paperclips [ https://substack.com/redirect/a2edb1cf-0c8f-4e8e-ab27-7b6cae34b14d?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]. On the eval side, @hwchase17 [ https://substack.com/redirect/d1dbe0e8-f122-4673-a271-0ec3d9e39d61?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] announced a Trace Judge model for detecting trajectory errors at ~1/100th the cost of closed models.

/r/LocalLlama + /r/localLLM Recap
1. GLM-5.2 Extreme Local Inference Tests
GLM-5.2 753B (IQ1_S) fully local across 2×M5 Max over one TB5 cable — ~16 tok/s, llama.cpp RPC [video] [ https://substack.com/redirect/8cfca267-aaee-4ee2-be2f-4a5e82c615a2?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] (Activity: 377): A user reports running GLM-5.2 753B fully locally using Unsloth dynamic IQ1_S quantization: nominally ~1.6 bits but ~2.1 effective bits due to mixed higher-precision layers, yielding a 202GB on-disk model. The setup shards weights across 2× M5 Max systems with 128GB unified memory each over a single Thunderbolt 5 link using llama.cpp RPC, keeping all weights resident with no SSD paging and achieving ~16 tok/s generation, 16k context, and q8 KV cache; TTFT is prompt-length dependent due to prefill. Commenters found 16 tok/s for a 753B model over two Macs surprisingly high, with one asking whether the video appeared faster than reported. Another noted the setup is impressive but questioned how the very low-bit 753B quant compares on complex reasoning against a smaller higher-precision model such as a 70B at 4-bit.
A commenter questioned whether the reported ~16 tok/s for GLM-5.2 753B IQ1_S across 2× M5 Max over Thunderbolt 5 was accurate, noting the video appeared faster; another highlighted that while the throughput is impressive for a 753B local setup, the very low-bit IQ1_S quantization raises the technical question of reasoning quality versus a smaller 70B at 4-bit model.
One user provided comparative llama.cpp RPC-style benchmarks using an M3 Ultra Studio 256GB + M3 Max MBP 128GB running GLM-5.2-UD-IQ4_XS: 13.03 tok/s at 2,377 context tokens with TTFT 3.09s, 8.64 tok/s at 22,485 context with TTFT 2.33s, and 6.21 tok/s at 32,595 context with TTFT 5.53s.
