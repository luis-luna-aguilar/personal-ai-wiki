## **Why is GitHub breaking when its competitors aren't?**


--------------------
View image: (https://media.beehiiv.com/cdn-cgi/image/fit=scale-down,format=auto,onerror=redirect,quality=80/uploads/asset/file/069b079e-db78-49ff-bdf0-ca66a0e75d93/superhumanteam_a_software_engineering_team_working_on_fixing__5eb9c7ef-2d06-4299-9b38-e7a55130f51a_1.jpg?t=1777973343)
Caption: Source: The Code, Superhuman


--------------------
**X marks the exit.** For a full month, HashiCorp founder Mitchell Hashimoto kept a log, marking an "X" every single day a GitHub outage stalled his work. After seeing those marks pile up day after day, he finally walked away after eighteen years, [calling](https://mitchellh.com/writing/ghostty-leaving-github) the platform "no longer a place for serious work." Even GitHub's CTO has now [admitted](https://github.blog/news-insights/company-news/an-update-on-github-availability/) that the platform just wasn't built to handle the load from AI agents.

**The blame doesn't stick.** The same agent load hits Vercel, Sentry, and Railway every day, yet they’re all holding steady. GitHub's traffic didn't just skyrocket overnight; it’s been growing steadily for two years. So why is only GitHub [melting down](https://newsletter.pragmaticengineer.com/p/the-pulse-github-breaks)?

**Late to the curve.** GitHub didn’t see it coming. The COO is calling this load "unprecedented," but Google was already preparing for a 10x spike in code volume by mid-2025. GitHub didn't start its own plan until October. By February, the target had tripled. Now, two decades of tech debt and a half-finished Azure migration are dragging down every single fix.

**The default broke.** Most users won't quit because the ecosystem makes switching feel almost impossible. But GitHub used to be the default that just worked, and that is just not the case anymore. Hashimoto is taking Ghostty elsewhere, and [GitLab](https://about.gitlab.com/) is suddenly back in the conversation. If GitHub wants that trust back, they're going to have to earn it from the ground up, this time for the agent era.

## **How to secure your Claude Code projects**


--------------------
View image: (https://media.beehiiv.com/cdn-cgi/image/fit=scale-down,format=auto,onerror=redirect,quality=80/uploads/asset/file/095ea4c2-27b5-405d-9233-ae7d84de83cb/superhumanteam_a_software_engineer_sitting_at_a_desk_typing_o_5650cccb-5ee5-4366-8ced-a6406a67f2e7_2.jpg?t=1777973263)
Caption: 


--------------------
Whenever Claude runs “npm install” or any shell command, it does so with your full user permissions. A malicious package could easily read your SSH keys, copy your .env files, or access anything else in your home directory. 

This [fix](https://code.claude.com/docs/en/sandboxing) keeps Claude locked inside your project folder, ensuring that nothing it executes can reach the rest of your machine. Run this command inside Claude Code:

```
/sandbox
```
Select "accept-edits mode." Claude can now read, write, and run commands within the project, but the moment something tries to touch a file outside that scope, the OS blocks it immediately.
