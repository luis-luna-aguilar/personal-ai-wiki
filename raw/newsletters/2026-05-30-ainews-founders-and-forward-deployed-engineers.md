Agent Harnesses, Multi-Turn RL Bugs, and the Infrastructure Around Autonomy
A subtle but important RL failure mode got called out: @ClementDelangue [ https://substack.com/redirect/69bab2e5-3051-4f77-9636-d5634e3c0b5a?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] highlighted a Hugging Face deep-dive on why many tool-using, multi-turn RL training loops are silently broken. The core bug: decoding model output, parsing tool calls, then re-tokenizing the updated conversation can change tokenization, so gradients are applied to sequences the model never actually sampled. The proposed fix is a strict “Token-In, Token-Out” rule: never re-encode sampled tokens; keep a single token buffer across turns. @johnschulman2 [ https://substack.com/redirect/96026fa1-1733-4a0b-aaba-10452cf926ed?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] reinforced the broader point that renderers are foundational infrastructure between messages and tokens, with failure modes spanning train/test mismatch, caching inefficiency, and prompt injection risk.
Harness design is becoming its own optimization discipline: @omarsar0 [ https://substack.com/redirect/b98cb785-100c-455b-9d76-e73f8c4c8f0e?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] surfaced work on Effective Feedback Compute (EFC), claiming raw token/tool counts explain agent success poorly while EFC reaches R² up to 0.99, implying harness quality matters more than gross activity. This lines up with productized tuning efforts like @LangChain [ https://substack.com/redirect/7e104f74-0073-4a4f-bcf9-38d1a7c09a19?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], where Deep Agents v0.6 makes harness profiles first-class to get strong performance from Qwen/Kimi/DeepSeek at 20x+ lower cost than frontier APIs, and @hwchase17 [ https://substack.com/redirect/3995f64c-6a36-441c-96e2-8ac3ae029bbf?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] explicitly framing “different models need different prompts/tools.” @vllm_project [ https://substack.com/redirect/9683746a-a06f-4e9c-93d1-167daa742988?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] shipped native weight syncing APIs and improved pause/resume for async RL, and later added fastokens [ https://substack.com/redirect/63d7b729-0d72-4a8f-98d5-0f5ae4747ced?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], a Rust BPE tokenizer to reduce CPU tokenization bottlenecks in long-context/agentic workloads.
Debate is shifting from “single vs multi-agent” to where the abstraction pays: @OfirPress [ https://substack.com/redirect/f4332362-6800-416a-8436-7294ed0dac58?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] argued current multi-agent systems are mostly speedups, not capability unlocks; @scaling01 [ https://substack.com/redirect/5d236c0b-7149-4b05-9d14-3e1e261a19f3?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] took the opposite view, expecting swarm-style training to yield better planning and superintelligence-like behavior. Either way, the practical trend is clear: more teams are building around agent observability, traces, and continual improvement loops, e.g. @Vtrivedy10 [ https://substack.com/redirect/5293c23a-f340-4c74-a278-9a1fd7f4ee7b?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] on mining production traces for SFT/distillation and long-horizon continual learning.

1. Local LLM Performance: MoE Releases, Quants, VRAM Savings
StepFun 3.7 Flash [ https://substack.com/redirect/24667367-107e-4f5f-abe9-a498d2733c00?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] (Activity: 637): StepFun released Step 3.7 Flash [ https://substack.com/redirect/c453615c-adae-44ea-b1cb-bb5dac9c23dd?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], a multimodal MoE with 196B total parameters, 11B active, and a built-in 1.8B ViT, advertised for high-throughput agent workflows up to 400 TPS and reportedly runnable locally with ~128GB RAM. Reported benchmarks position it unusually strongly for a flash-class/local model: SWE-Bench Pro 56.26%, DeepSearchQA F1 92.82%, HLE w/tools 47.2, plus large gains over Step 3.5 Flash on Terminal-Bench, Toolathlon, ClawEval, and other agentic/tool-use tasks. Direct model artifacts are available on Hugging Face in BF16 [ https://substack.com/redirect/95f79079-2423-4516-90da-6b84fd1cb6bd?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], FP8 [ https://substack.com/redirect/3be442b5-5870-43c7-9bfb-71e092b41245?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], NVFP4 [ https://substack.com/redirect/198e4c8e-f70f-46a2-9c59-1faf29163126?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], and GGUF [ https://substack.com/redirect/3989fe9f-661d-4ad0-9240-8e9b29808b60?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ], with day-0 llama.cpp support PR [ https://substack.com/redirect/8f534f12-a36f-4e05-8812-38c690834bdd?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ] and related MTP work in llama.cpp#23274. Commenters characterize the model as technically odd: its hidden/thinking traces are described as nearly incoherent, but final answers can be “perfect” and competitive with much larger >1TB models; one user says the prior Step 3.5 “infinite thinking” issue appears fixed. There is cautious enthusiasm around local deployment, especially for users with 4x3090-class hardware, and appreciation that StepFun upstreamed llama.cpp support instead of only maintaining a fork.
StepFun released multiple Step-3.7-Flash checkpoints on Hugging Face: BF16 (Step-3.7-Flash [ https://substack.com/redirect/95f79079-2423-4516-90da-6b84fd1cb6bd?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]), FP8 (Step-3.7-Flash-FP8 [ https://substack.com/redirect/3be442b5-5870-43c7-9bfb-71e092b41245?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]), NVFP4 (Step-3.7-Flash-NVFP4 [ https://substack.com/redirect/198e4c8e-f70f-46a2-9c59-1faf29163126?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]), and GGUF (Step-3.7-Flash-GGUF [ https://substack.com/redirect/3989fe9f-661d-4ad0-9240-8e9b29808b60?j=eyJ1IjoiODlhdDlmIn0.psR-epQqK_Wbg6RTI-yQkSgRmDIqosMhU9elL-EoqO0 ]). One user reports the prior Step 3.5 Flash “infinite thinking” issue appears fixed, making 3.7 more usable despite still having an odd intermediate reasoning style.
