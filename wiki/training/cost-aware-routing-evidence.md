# Cost-aware routing: evidence from practice

Case studies and cost data behind [Cost-aware AI task routing](cost-aware-ai-task-routing.md)'s guidance: named model and harness comparisons, routing built as infrastructure, and the cost-variance cases that argue for measuring cost per completed task rather than list price or token counts.

## Case studies and data

### Model and harness selection wins

- **Bridgewater / Thinking Machines finance case.** Thinking Machines reports that Bridgewater AIA Labs used expert-labeled data to train a Qwen3-235B model for six investor information-filtering tasks. Frontier models with naive prompts averaged roughly 50% accuracy; expert prompts raised them to the mid-70s; the final trained model improved from 78.2% to 84.7%, made 29.8% fewer mistakes than the best frontier model evaluated, and reduced inference cost per task by 13.8x. The routing lesson is durable: for repeated expert-judgment tasks, domain examples and smaller tuned models can beat generic frontier defaults on both quality and cost.
- **Spiral / OpenRouter routing.** Every reports Spiral uses 12 models through OpenRouter: Sonnet 4.6 for most prose, Gemini 2.5 Flash for a top-edit pass that removes AI tells, and a smaller OpenAI model for file summaries. The reason is not only price: OpenRouter also standardizes provider APIs and provides fallback paths when one provider is unavailable.
- **Fable for unknowns.** Every reports using Fable to find missing questions, hidden standards, and invalid targets before execution. In one workflow, Fable diagnosed that a copy-editing target was unvalidated; in another, it turned a video-clipping job into scripts and instructions that a cheaper model could reuse.
- **OpenAI stale-experiment audit: compare model and effort on the real task.** On one Codex audit of 6,000+ files (1M+ lines of Python, TypeScript, Go and Rust), GPT-6 Astra Ultra produced 142 accepted findings for $109.06 ($0.77 each), GPT-6.1 Sol Ultra 131 for $15.12 ($0.12), and GPT-6.1 Sol Medium 86 for $5.27 ($0.06); costs include research subagents and automatic follow-up turns. Reviewing the gap (mostly constant flags used as dependencies of other flags) let the team write prompt corrections so the cheaper model closes it, corrections it plans to revisit when new models ship.
- **Anthropic's own tier split for Haiku 5.5.** Anthropic positions Haiku 5.5 for scoped, high-volume work such as compaction, summarization and subagents, and keeps [Sonnet 5.5](../models/claude-sonnet-5-5.md) and [Opus 5.5](../models/claude-opus-5-5.md) for complex agentic coding (Terminal-Bench 4.0: 39.2% against Sonnet 5.5's 70.6%). Haiku is cheapest on prompts under 100k tokens ($0.10/$0.50 per 1M), which made up about 90% of Haiku 4.5's requests. Cognition reports Devin Fusion holds FrontierCode 66.2 with Haiku 5.5 as the sidekick under an Opus 5.5 lead, at lower cost and latency. Independent tests temper the price story: Haiku 5.5 writes about 3x GPT-6 Luna's output tokens per task at max effort, and Vals finds it costs more per test than Haiku 4.5 on every shared benchmark, so a cheaper token does not guarantee a cheaper task. See [Claude Haiku 5.5](../models/claude-haiku-5-5.md).
- **Anthropic: effort buys verification, not a better approach.** Thariq Shihipar's pass through every Terminal-Bench 3.0 result found that higher effort mostly adds testing and edge-case checking. Moving Fable 5.1 from low to max raised passes from 140 to 214 of 370 attempts, at a median of 222k tokens per attempt against 73k, and cut "missed a case" failures from 59 to 24, while "made the wrong call" failures only fell from 133 to 107. Gains were largest in security (64% to 87%) and hardware (34% to 75%) and smallest in operations (12% to 22%). With a detailed spec the levels converge, so pay for effort where checking is the work. The working loop is on [AI enablement — software development](ai-enablement-software-development.md).

### Routing as infrastructure

- **Eval data, not the router, is the moat.** With several frontier models shipping in the same month, picking the right one for a task has become its own problem, and routing itself has commoditized — OpenRouter, Azure, and generic open-source routers all offer one. What none of them supply is the eval data that tells a router what "good" looks like for a specific workload: Not Diamond trains custom routers from a customer's own uploaded, scored examples, and the same approach powers OpenRouter's "Auto" mode. Cognition's Devin Fusion is a concrete instance of the mechanism working: running on Fable 5, it can beat Opus 4.8 on cost per task not because Fable is cheaper, but because stronger delegation and judgment mean fewer wasted actions — in 81% of sampled Fable-led runs, the lead model never makes a code edit itself (per AINews, relaying an independent coding-agent index analysis).
- **Databricks' real-PR coding-agent benchmark.** Databricks built a private benchmark from real pull requests its own engineers had already completed in a multi-million-line production codebase, grading agents against each PR's original tests — a task set no model has trained on. Findings: open-source GLM 5.2 matched Claude Opus 4.8's quality at roughly 30% lower cost per task; running the *same* model with the same thinking effort through different coding harnesses (Claude Code/Codex vs. Pi) produced a >2x cost difference at equal quality — Pi sent roughly 3x less context per turn and finished in fewer runs, though Databricks is explicit that this isn't "Pi is always cheaper," just that harness choice is an independent variable from model choice; and per-token sticker prices mislead — in this benchmark Sonnet 5 cost $2.09 per completed task versus Opus's $1.94, despite Sonnet's lower per-token rate, because it took longer and re-read more context. Databricks argues a team's own merged PRs, with passing tests, are an untapped, model-agnostic eval set — the routing lesson extends from "which model" to "which model *and* which harness, measured per completed task."
- **Databricks' internal AI FinOps breakdown.** Separately from its coding-agent benchmark, Databricks detailed how it cut its own internal AI coding spend by up to 90% in some scenarios while usage kept growing: shifting defaults to cheaper/more efficient models (~50% of the savings), smart routing (~30%), user visibility and adaptive budgeting (~10%), and pruning context bloat plus harness tuning (~10%). The breakdown is a concrete example of [Cost-aware AI task routing](cost-aware-ai-task-routing.md)'s FinOps controls actually applied at scale, not just recommended.
- **Arkadium's Game Lab.** Game publisher Arkadium, working with Every's Good Start Labs, Meta, and DeepMind on a public model-vs-human game leaderboard, found that frontier models making novel math and science discoveries lose about 90% of their Gin Rummy games against casual players — because frontier training data contains almost no Gin Rummy. Arkadium's fix was a purpose-built 4.6-million-parameter model (an 18MB file, runs on a regular CPU) that beats human players roughly 90% of the time. At 1 million requests/day, it costs about $60/year to run, versus multi-millions for an equivalent-volume frontier LLM — a concrete cost ratio for routing well-defined, out-of-distribution-for-frontier tasks to a narrow specialist instead.
- **Enterprise routing becomes a business layer of its own.** The same week Stripe's reported $7B acquisition of OpenRouter closed (on ~$140M ARR, ~70% gross margin, and 250T tokens/month routed, up from 50T in February), Glean detailed its own three-tier enterprise routing architecture — a pre-model "raw materials" filtering layer (Waldo) plus continuous AI-judge evaluation of the router's choices on sampled live traffic — and claimed roughly 4x cost-efficiency versus Claude Cowork ($0.45 vs. $1.84/task). Both data points reinforce that routing/aggregation is becoming valuable infrastructure in its own right, not just a convenience layer on top of model choice. See [OpenRouter](../tools/openrouter.md) and [Glean](../tools/glean.md).
- **AT&T's open-model routing at scale.** AT&T reportedly routes 40% of employee AI usage to open models today, with an explicit target of 60-70%, citing coding costs down 56% for only a ~2% quality drop at 45B tokens/day (via a Twitter summary of AT&T's internal deployment, not an AT&T primary statement). Framed by outside commentary as a warning sign for closed-frontier labs' enterprise moat, and cited by Ollama as validation for open-model adoption at scale — a named Fortune-500 data point alongside this page's Databricks and Every case studies.
- **Task-specific small models as a commodity API.** [ScaleDown](../models/scaledown.md) sells single-task classify, extract, summarize and compress models at a flat $0.05 per million input tokens, output free, via API or OpenRouter; it packages the routing page's advice to route classification and extraction to small models and trims context before a frontier call.
- **Decision models for the yes/no steps.** Many agent steps are classifications, not generation. [Decision models](../concepts/decision-models.md) such as [Jev](../models/jev.md) return a calibrated probability for about $0.04 per million input tokens, output free. A Jev-as-a-judge paper reports that escalating only low-confidence calls to GPT-6 Astra keeps 99% of accuracy at 57% of the cost. LangChain says routing each Open SWE step to the cheapest adequate model cut median cost per task by 64%. Every's rule for the split: if a person could make the call in under 10 seconds, it goes to the decision model.
- **Every Agent: fix waste before building a router.** Every first sent all Every Agent work through a Sonnet coordinator told to escalate hard jobs to Opus; quality and speed fell and cost rose, because many requests ran on both models. Engineer Paridhi Agarwal hunted waste instead: Opus 5.5, shorter tool outputs and deferred tool definitions (about 10%), and a cache bug where each user's Slack ID in memory-folder names made every system prompt unique (−74% in a best-case test). Together these cut cost on 11 frequent tasks by over 80%. Her audit: have the agent explain the system first, prefer features you already pay for, measure each change before and after including quality, then trace what is still expensive.

### Cost variance and budgeting tradeoffs

- **Every's Sol cost spike.** Every's head of operations, Arielle Shipper, reports daily AI credit usage rose from 11,520 to 26,685 credits (~2.3x) in the first five full days after GPT-5.6 Sol rolled out — an unbudgeted spike on top of an already-elevated Fable-driven baseline, briefly zeroing out the company's payment card overnight. Her explicit choice: no hard token budgets yet, because staff use whichever model works best for a given job (no single-model standardization) and the cost mix shifts too fast — any fixed allocation scheme "would be obsolete in days, if not hours." A counterpoint to the token-budget controls on [Cost-aware AI task routing](cost-aware-ai-task-routing.md): flexible, closely-watched spend can beat a rigid budget when task-to-model fit is still unsettled.

- **Cost-normalized agent benchmarks widen the gap between "most capable" and "best value."** Together AI found GLM-5.3 completes 5x more DeepSWE work than Fable 5 under a fixed $100 budget (~17 vs. ~3 solved tasks) despite similar first-try quality; GPT-5.6 Sol Max scored 72.7% on DeepSWE v1.1 for $6.47/task versus Fable 5 Max's 69.7% for $21.63/task; and Cline found a stealth model (Ox Alpha) solving a real bugfix using roughly 3x fewer output tokens than Fable. Separately, Every reports Fable — despite being "the most capable model on the market" — accounted for only 6% of Anthropic's purchased tokens and 11% of model spend a month after launch, largely because it lacks a zero-data-retention option many enterprises require outright; Every's own head of tech consulting reports "no relative gain from Fable on 80 percent" of his knowledge-work tasks. Read together, these argue for routing by cost-normalized task completion rather than raw capability score whenever a cheaper model clears the quality bar.
- **Cursor's agent-swarm planner-cost comparison.** Running an identical multi-agent build task (implementing SQLite from scratch in Rust) across four model mixes at similar final quality, Cursor found dramatic cost variance driven by planner choice: $1,339 with an Opus 4.8 planner + Composer 2.5 workers, versus $10,565 with GPT-5.5 for both roles. Workers carried 69-90%+ of total tokens in every configuration, but planner tokens cost disproportionately more per token — reinforcing that routing the planning/decomposition role to a cost-efficient-but-capable model, while keeping workers cheap, matters more than optimizing worker-model cost alone.
- **Uber's benchmark-driven model selection.** Uber benchmarks every managed agent against its own real work before picking a model, then keeps moving as the frontier shifts: build a benchmark from the agent's actual task, run it on a harness that serves any model behind one interface, and move to whatever is Pareto-optimal on cost/completed-task, quality, and reliability. Its AI code-review tool, uReview, is graded against real pull requests with known bugs (precision/recall/F1, plus cost/PR, latency, timeouts, noise); switching models improved F1 while cutting cost/PR. A separate internal "Uber SWE Benchmark" (thousands of real PRs across large monorepos) informs model choice across all of Uber's SDLC-managed agents. The single most impactful — and still-growing — lever isn't the primary model, it's the subagent default: subagents are set to a cheaper model since they execute well-defined, delegated work that rarely needs frontier-level reasoning, while the primary model handles decomposition and evaluation, with manual override available per session.
- **Agent teams cost more than they usually return.** Vals AI ran GPT-6 Sol and Opus 5.5 on Vibe Code Bench alone and as multi-agent teams: teams cost 1.8–5.1x more, and only Sol at medium effort improved significantly (+7.3 points). Opus ran sequential waves of subagents for no significant gain. Treat a team configuration as something to measure against a single agent on your own task, not a default upgrade; vendors give the same advice (Anthropic and Cognition both say to try multi-agent workflows on a scoped slice first). See [Multi-agent coordination evidence](../workflows/multi-agent-coordination-evidence.md).
- **A lower list price is not a cheaper task.** Claude Opus 5.5 cut list prices 20% from Opus 5, but at max effort Artificial Analysis measures $5.98 per task against Opus 5's $5.86, because the newer model uses far more tokens; the advertised ~40% saving holds only at default effort. Higher effort can also lower quality: on FrontierCode, xhigh cost 2.8x medium for a 3.2-point lower score. Compare models on cost per completed task at the effort you will actually run. See [Claude Opus 5.5](../models/claude-opus-5-5.md).
- **Per-task cost can fall while token use rises.** Artificial Analysis measured [GPT-6.1 Sol](../models/gpt-6-1-sol.md) at $0.72 per Intelligence Index task at max effort, against $1.04 for GPT-6 Sol and $3.26 for GPT-6 Astra, even though 6.1 Sol emits 10–30% more output tokens than its predecessor. The saving comes from fewer turns and a cheaper cache-read price. Compare candidates on measured cost per completed task, not on list price or token counts.
